Set up the companion

  1. Install NetGauge on an iPhone running iOS 26 or later and the companion on a Mac running macOS 26 or later. Use the builds supplied with your beta; App Store links will be added after release.
  2. Connect both devices to the same local network. Keep the Mac awake and the companion running. Guest Wi-Fi and networks with client isolation may prevent device-to-device connections.
  3. Allow local-network access when requested. Open the Mac companion’s server controls and start the server.
  4. On iPhone, open LAN and select the discovered companion. Follow the pairing prompt and compare the check code displayed on both devices.
  5. Approve only when the codes match. If they do not, reject the request and start pairing again. Once connected, run a local test.

A cloud account is not needed to pair devices. To see the same cloud projects on both, sign in with the same account.

Choose the right test

  • WAN: Internet speed and latency using M-Lab. Requires Internet access and consent to its public measurement collection.
  • Gateway latency: checks response time to your local gateway.
  • Local throughput: measures traffic between your iPhone and Mac using native iPerf. Both apps are required.
  • Advanced tests: Alta iPerf3 tests your iPhone against an Alta router or access point, with no Mac needed (see below). HTTP throughput, UDP and Path Check offer additional diagnostics. Follow each feature’s companion and connectivity instructions.

Wi-Fi conditions, selected adapters, VPNs, background traffic and the test destination can affect results. Test measurements are not a guaranteed Internet-service speed.

Set up Alta iPerf3

Alta iPerf3 measures throughput between your iPhone and an Alta Labs router or access point, using the iperf3 server built into the device. NetGauge signs in to the device over SSH, starts that server for one test, and stops it afterwards. It changes no settings on the device. You need administrator access to the site in the Alta controller.

  1. In NetGauge, open LAN → Advanced Tests. Alta iPerf3 is the first card. Tap its key button to open Router Setup, then Copy Key or Share.
  2. Sign in to the Alta controller (the website works on iPhone too), open the site, and go to Settings → System → SSH Keys. Add the key and save.
  3. Wait about a minute for the devices to apply it. One key covers every Alta router and access point in that site.
  4. Back in Alta iPerf3, the address is your router’s. To test an access point instead, type its address (shown in the Alta controller). Tap Start router test.
  5. The first test with each device asks you to confirm it and shows its key fingerprint. Tap Trust and Test. NetGauge remembers it.

Each test runs a 12-second download and then a 12-second upload, the first 2 seconds of each being warm-up. The device’s own processor sends and receives the traffic, so the result is the speed between your iPhone and that device, not how fast the router routes. Results save to projects like other LAN tests, labeled iPerf3 (Router) with the device’s model and address.

“The router refused this iPhone’s key”

The key is not in that site’s SSH Keys yet, or it was removed or replaced. Copy it again from Router Setup, add it in the controller, wait a minute and retry. A new iPhone, or Replace Key, needs the new key added.

“This router isn’t supported yet”

Alta iPerf3 works only with Alta Labs routers and access points. Check that the address is an Alta device, not a switch, modem or another brand.

The result says Wi-Fi dropped during the test

Wi-Fi disconnected for part of the test. If it reconnected in time, the test finished, but its average includes the time with no connection, so it reads lower than the link really is. Run the test again for a clean result.

Remove NetGauge’s access to a site

Delete the key in the Alta controller under SSH Keys. That ends access to every device in the site straight away. Removing a device from Router Setup’s trusted list only makes NetGauge ask again next time; it does not remove access.

Accounts and saved projects

Sign in or create an account

Open Account and choose Google or email. For email signup, complete any confirmation message before signing in. Sign in the same way on both devices to access the same cloud projects. Guest projects are not automatically the same as account projects.

Reset an email password

Open the email sign-in screen and choose Forgot password. Enter your email, open the reset message on the device where you want to complete recovery, and choose a new password. If the link expires, request a new one. Google accounts sign in through Google and use Google’s account-recovery process.

Projects are missing or sync failed

Confirm the account email and sign-in method on both devices. Check Internet access and the account’s sync status. On iPhone, review Data & Sync and use the available manual sync action. Guest projects may need importing; a different account may have a different project set. Keep the original device’s data until you confirm the cloud copy.

Export saved results

Use the project export controls to save CSV or PDF. On Mac, choose the destination in the system save dialog. Open the file to confirm it saved successfully. Exports may include addresses, notes and network details; review before sharing.

Privacy and account deletion

Read the privacy policy for collection, sharing and retention details.

Withdraw WAN consent

Open WAN settings and choose Withdraw WAN consent. This stops the active WAN test and provider lookup. The next WAN test asks for consent again. Withdrawal does not erase data already published by M-Lab.

Delete your account

Sign in, open Account and choose Delete Account. Read the consequences and type DELETE when prompted, then confirm. Keep Internet access available until the app reports the result. Account deletion removes your cloud account and its associated data; exported files, M-Lab results and guest projects on other devices remain. If deletion fails, retry or contact support without sharing credentials.

Troubleshooting the connection

The companion is not discovered

Confirm the server is running, the Mac is awake, both devices use the same reachable LAN, and local-network access is allowed. Check VPN routing, macOS firewall settings and router client isolation. Allow the companion’s needed connections rather than disabling your firewall. Restart the companion server and scan again.

A previously paired companion no longer connects

The Mac may be asleep or its address may have changed. Wake it, reopen the companion and rescan. If pairing was removed or app data was reset, pair again and compare both codes. Update both apps together if one reports an incompatible version.

A WAN test or provider lookup fails

Check Internet access and WAN consent. Retry after stopping the previous test. M-Lab or IPinfo may be temporarily unavailable; local tests can still be useful. If a VPN is active, its route may be the connection being measured.

Access was denied

Review the app’s permissions in system settings. Enable local-network access for companion discovery if available. For an export, choose a folder you can write to. You can continue using features that do not need the denied access.
